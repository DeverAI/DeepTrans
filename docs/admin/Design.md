# DeepTrans - 设计文档

## 项目概述

DeepTrans 是一个基于 PyQt6 开发的桌面智能翻译助手，旨在为用户提供便捷的文本翻译服务。该应用支持机械翻译和AI翻译两种模式，通过悬浮窗口和系统托盘提供友好的用户界面。

## 核心架构

### 整体架构图

```
DeepTrans
├── 主程序层 (Main Layer)
│   ├── DeepTransApp: 应用主控制器
│   ├── Worker: 异步任务处理器（带兜底错误结果与结果ID追踪）
│   └── CLI: 命令行参数解析 (--config/--debug/--no-tray/--portable)
├── 核心业务层 (Core Layer)
│   ├── monitor: 文本监控引擎
│   ├── translator: 翻译引擎（双AI后端 + 机械翻译）
│   ├── config: 配置管理与路径解析
│   ├── errors: 错误分析与落盘
│   └── i18n: 国际化支持
├── 界面层 (GUI Layer)
│   ├── overlay: 悬浮翻译窗口
│   ├── settings: 设置窗口（含 AI 引擎切换）
│   ├── about: 关于窗口
│   ├── tray: 系统托盘（含 ENABLE_TRAY 模块开关）
│   └── styles: 样式管理
└── 工具层 (Utils Layer)
    ├── errlog: Err.log 自动存错机制
    └── icon_gen: 图标生成工具
```

### 模块设计

#### 1. 主程序模块 (main.py)

**职责**：
- 应用初始化和生命周期管理
- 各模块协调和信号连接
- 异常处理和错误恢复

**核心组件**：
- `DeepTransApp`: 主应用控制器
- `Worker`: 异步任务执行器

**设计模式**：
- **观察者模式**：通过信号槽机制实现模块间通信
- **工厂模式**：动态创建和配置界面组件
- **单例模式**：配置管理和全局状态

#### 2. 文本监控模块 (core/monitor.py)

**职责**：
- 全局文本选择监控
- 热键管理和触发
- 文本预处理和过滤

**核心功能**：
- 全局钩子注册（pynput 鼠标监听 + keyboard 库热键）
- 文本提取和清理（模拟 Ctrl+C 经剪贴板获取划词文本）
- 延迟触发机制（可配置防抖延迟）
- 状态管理和切换（线程安全的 enabled 属性，Lock 保护）

**技术实现**：
- 使用 PyQt6 的全局事件监听
- 实现防抖机制避免频繁触发
- 支持多语言文本识别

#### 3. 翻译引擎模块 (core/translator.py)

**职责**：
- 统一的翻译接口
- 多翻译引擎支持
- 结果缓存和优化

**AI 翻译引擎**（均为 OpenAI Chat Completions 兼容协议，经 openai SDK 统一调用）：
- **Xiaomi MiMo**（默认）：token-plan-cn.xiaomimimo.com/v1，模型集 mimo-v2.5 / mimo-v2.5-pro / mimo-v2-pro
- **DeepSeek 官方**：api.deepseek.com，模型集 chat / reasoner

引擎定义集中于 core/config.py 的 AI_PROVIDERS 表（base_url、密钥字段名、模型映射），新增引擎只需扩展该表；translator 层按当前 provider 装配客户端，仅在密钥或端点变化时重建。

**机械翻译引擎**：
- **MyMemory**（主选）与 **Google**（回退），由 deep-translator 库提供
- 语言码按各家大小写规则映射（如 MyMemory 要求 en-US/zh-CN 形式）
- 进程级 socket 默认超时 20 秒兜底，防止不可达端点悬挂 Worker

**设计特点**：
- **策略模式**：可插拔的翻译引擎
- **适配器模式**：统一不同API接口
- **缓存机制**：减少重复翻译请求

#### 4. 配置管理模块 (core/config.py)

**职责**：
- 配置文件读写（原子写入：临时文件 + os.replace）
- 配置验证和默认值（VALIDATORS 校验表，非法值回落默认并记录）
- 配置损坏自愈（JSONDecodeError 时备份为 .corrupted 并用默认配置继续运行）

**路径解析设计**：
- app_dir()：开发态为仓库根目录；PyInstaller 冻结态为 exe 所在目录
- resource_dir()：冻结态取 sys._MEIPASS 解包目录，用于只读资源
- icon_path()：图标绝对路径解析，先解包目录后程序目录
- --config / --portable 在模块导入期解析，保证 cfg 单例创建前路径即已确定

**恢复默认策略**：
- reset(keep_keys) 保留 API 密钥字段，防止误清空；确认弹窗文案同步注明

**配置项**：
- AI 引擎选择与两家密钥
- 界面样式和布局
- 功能开关和行为设置

#### 5. 国际化模块 (core/i18n.py)

**职责**：
- 多语言支持
- 文本本地化
- 语言切换管理

**支持语言**：
- 中文（简体）
- 英文
- 可扩展其他语言

#### 6. 界面模块

##### 6.1 悬浮翻译窗口 (gui/overlay.py)

**职责**：
- 显示翻译结果

**功能特性**：

- 半透明和圆角设计

##### 6.2 设置窗口 (gui/settings.py)

## 全局错误自动存错设计 (utils/errlog.py)

- 所有运行时错误必须落盘：log_error / log_warning / log_exception 三个入口
- main.py 安装全局 sys.excepthook，未捕获异常先写 Err.log 再走原处理链
- 路径规则与 core/config 一致（开发态仓库根目录、冻结态 exe 目录），但独立实现避免循环导入
- 写日志本身绝不允许抛出新异常（内部捕获 OSError 静默放弃该条记录）
- 维护流程：修复前读 Err.log，修复完成后清空内容（不删除文件）

## 错误处理与线程模型补充

- Worker(QThread)：run() 内异常时返回与正常结果同构的 error_result 兜底值，杜绝线程静默死亡导致界面停在"翻译中"状态
- 结果竞态：每次发起新翻译递增 worker_id，回调校验丢弃过期结果
- 机械翻译/翻译函数内部全面捕获异常并以结果字符串返回错误信息

## 数据流设计

### 翻译流程

```
用户选中文本 → 监控器捕获 → 文本预处理 → 翻译引擎调用 → 结果处理 → 界面显示
```

### 详细流程

1. **文本捕获阶段**
   - 全局钩子监听鼠标选择事件
   - 经剪贴板提取选中的文本内容
   - 进行文本清理和格式化

2. **翻译准备阶段**
   - 检查配置和API密钥
   - 确定翻译模式和语言对
   - 应用翻译提示词（如配置）

3. **翻译执行阶段**
   - 并行调用多个翻译引擎（可选）
   - 处理翻译结果
   - 进行结果验证和优化

4. **结果展示阶段**
   - 格式化翻译结果
   - 更新界面显示
   - 提供用户交互选项

## 界面设计

### 设计原则

- **简洁性**：界面简洁明了，功能直观
- **一致性**：保持统一的视觉风格
- **响应性**：快速响应用户操作
- **可访问性**：支持键盘和鼠标操作

### 颜色方案

- **主色调**：`#3C6EF0`（蓝色）
- **背景色**：`#FFFFFF`（白色）
- **文字色**：`#000000`（黑色）
- **辅助色**：`#6C757D`（灰色）

### 字体规范

- **主字体**：Segoe UI（Windows默认）
- **字号**：12px（正文），14px（标题）
- **字重**：Regular（常规），Medium（标题）

## 错误处理设计

### 错误分类

1. **配置错误**
   - API密钥无效
   - 配置文件格式错误
   - 配置项缺失

2. **网络错误**
   - API连接失败
   - 网络超时
   - 服务器不可用

3. **翻译错误**
   - 翻译服务返回错误
   - 文本格式不支持
   - 翻译结果为空

4. **界面错误**
   - 窗口创建失败
   - 样式加载错误
   - 信号连接失败

### 错误处理策略

- **优雅降级**：部分功能失败时保持核心功能可用
- **用户友好提示**：提供清晰的错误信息和解决建议
- **自动重试**：网络错误时自动重试
- **日志记录**：详细记录错误信息便于调试

## 性能优化

### 内存管理

- **对象池**：复用界面组件减少内存分配
- **延迟加载**：按需加载模块和资源
- **资源清理**：及时释放不再使用的资源

### CPU优化

- **异步处理**：耗时操作使用后台线程
- **结果缓存**：缓存翻译结果避免重复请求
- **防抖机制**：减少频繁触发的事件处理

### 网络优化

- **连接池**：复用HTTP连接
- **批量请求**：合并多个翻译请求
- **压缩传输**：减少网络传输数据量

## 安全设计

### API密钥管理

- **本地明文存储**：密钥保存在本地 config.json 中，不经过任何第三方上传或同步
- **权限控制**：严格限制 API 密钥的使用范围（仅用于对应引擎请求头）
- **密钥保留策略**：恢复默认设置时保留密钥字段，避免误清空
- **轮换方式**：直接编辑 config.json 或在设置窗口更新；translator 检测到密钥变化自动重建客户端

### 数据安全

- **本地存储**：翻译结果仅在本地存储
- **数据清理**：及时清理敏感信息和临时数据
- **访问控制**：限制对配置和数据的访问权限
